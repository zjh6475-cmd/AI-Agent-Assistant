# AI-Agent-Assistant 用人部门审核 Demo

这份材料用于在 8～10 分钟内向用人部门展示项目的业务闭环、技术方案和工程能力。

## 一、先向审核人员说明项目是什么

这是一个面向企业内部知识问答的 AI Agent 助手。用户可以登录系统、创建聊天会话、上传企业文档，并通过普通聊天或 Agent 模式完成问答。

项目的核心目标不是“调用一次大模型”，而是把一条可落地的链路做完整：

```text
用户登录
  → 创建会话
  → 普通 AI 对话 / Agent 对话
  → 上传 PDF、DOCX、TXT 文档
  → 文本解析与分块
  → 本地 Embedding 向量化
  → Chroma 向量检索
  → 证据校验与来源展示
  → SSE 流式返回结果
```

Agent 模式在此基础上增加了：

```text
用户问题
  → LangGraph 状态图
  → 模型判断是否需要工具
  → SQL 工具 / 知识库工具
  → 工具错误重试与次数限制
  → 记录执行步骤和来源
  → 返回最终答案
```

## 二、推荐演示顺序

### 1. 展示登录和多会话

1. 注册一个演示账号并登录。
2. 点击“新聊天”。
3. 发送：`你好，请介绍一下你能做什么。`
4. 新建第二个会话，说明不同会话的历史记录相互隔离。

需要强调的能力：

- JWT 登录认证；
- 用户只能访问自己的会话和文档；
- 会话标题可以修改、删除；
- 聊天记录持久化到 SQLite。

### 2. 展示普通 AI 对话和流式输出

发送：

```text
请用三句话解释什么是 FastAPI，并给出一个适合初学者的使用场景。
```

观察回答不是一次性出现，而是通过 SSE 流式显示。

向审核人员说明：普通聊天不强制检索知识库，适合通用知识问答；用户勾选 Agent 模式后，系统才会进入 LangGraph 工具调用流程。

### 3. 展示 RAG 知识库问答

上传 `review/demo_data/公司报销制度-演示版.txt`，等待文档处理完成。

然后提问：

```text
差旅住宿每天的报销上限是多少？需要提供什么材料？
```

预期现象：

- 系统从上传文档中检索相关片段；
- 回答包含文档来源；
- 不需要用户把整份文档复制到输入框；
- 不相关内容不会作为答案依据。

接着提问：

```text
这份制度规定了公司的训练数据集名称吗？
```

预期现象：系统应说明文档没有该信息，而不是编造一个名称。

这一步重点展示项目的防幻觉思路：召回到相关主题，不等于证据中真的存在问题所需事实，因此增加了证据锚点校验和不足时拒答。

### 4. 展示 Agent 工具调用

勾选 Agent 模式，发送：

```text
我刚才上传了几份文档？最近上传的文档有哪些？
```

预期现象：

- LangGraph 根据问题判断需要查询工具；
- SQL 工具读取当前用户的数据；
- 页面展示执行步骤或来源；
- 最终答案只返回当前用户自己的数据。

再发送一个知识库问题：

```text
请根据我上传的公司报销制度，说明交通费报销要求。
```

预期现象：Agent 选择知识库工具，检索文档后回答并展示来源。

### 5. 最后展示测试和工程质量

在后端目录执行：

```powershell
..\venv\Scripts\python.exe -m pytest tests -q
```

审核时可以说明测试覆盖了：

- 登录、注册、JWT 鉴权；
- 会话创建、修改、删除和数据隔离；
- 普通聊天与 Agent 接口；
- SQL 工具边界；
- RAG 检索、来源和证据不足拒答；
- 工具错误处理、重试和提示词约束。

## 三、项目技术栈

| 模块 | 技术 | 作用 |
|---|---|---|
| 前端 | React、Vite | 登录、聊天、文档管理和流式展示 |
| 后端 | FastAPI | API、鉴权、文件上传和 SSE |
| Agent 编排 | LangGraph | 状态管理、条件路由、工具调用和重试 |
| 模型接入 | DeepSeek、LangChain | 普通问答和工具调用 |
| RAG | Chroma、BAAI/bge-small-zh | 向量化、召回和来源追踪 |
| 数据持久化 | SQLite、LangGraph Checkpoint | 用户数据、聊天记录和 Agent 状态 |
| 测试 | pytest | API、工具、图流程和 RAG 可靠性测试 |
| 部署 | Docker Compose、Nginx | 前后端统一启动和 SSE 反向代理 |

## 四、面试时建议这样讲项目难点

### 难点 1：普通聊天和 Agent 聊天如何共存

系统将两条链路分开：普通聊天直接调用模型，Agent 聊天交给 LangGraph 编排。这样可以避免所有问题都强制走工具，降低延迟和 Token 消耗。

### 难点 2：如何避免 RAG 答非所问

不是只增加召回数量，而是采用“召回 → 距离阈值 → 证据锚点校验 → 有依据回答或拒答”的链路，并在评测用例中验证误召回时不能编造答案。

### 难点 3：工具调用失败怎么办

Agent 图中对工具异常进行结构化记录，并限制重试次数；达到上限后返回可理解的失败结果，避免无限循环。

### 难点 4：为什么使用 SSE

模型回答和 Agent 执行步骤都可能耗时，SSE 可以让前端持续接收增量内容和状态事件，改善用户等待体验，同时保留执行过程可观察性。

## 五、审核人员可以检查的入口

- Docker Compose 部署：浏览器访问 `http://localhost`。后端端口只在 Docker 内部网络开放。
- 本地开发模式：前端 `http://localhost:5173`；后端健康检查 `http://127.0.0.1:8000/`；API 文档 `http://127.0.0.1:8000/docs`。
- 自动化测试：`backend/tests`
- 脱敏流程回放：[`agent-replay-bundle.json`](demo_data/agent-replay-bundle.json) 和 [`agent-replay-rag-003.json`](demo_data/agent-replay-rag-003.json)。它们用于离线展示，不会发起新的模型请求。

## 六、演示时不要展示的内容

不要把以下文件发给审核人员：

- `backend/.env`；
- 真实 API Key；
- 含有个人聊天记录的 `chat.db`；
- 个人知识库 `vector_db`；
- 个人上传文件和 Agent checkpoint 数据库。

建议使用本目录中的虚拟演示文档，并让审核人员现场看到“上传文档 → 检索 → 来源 → 拒答”的完整过程。
