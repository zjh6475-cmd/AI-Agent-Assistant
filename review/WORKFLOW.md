# AI-Agent-Assistant 工作流说明

## 1. 用户和会话流程

```text
注册 / 登录
  ↓ JWT Token
创建或选择会话
  ↓ 用户身份校验
发送问题
  ↓ 保存用户消息
普通聊天 或 Agent 模式
  ↓
保存 AI 回复并返回前端
```

数据隔离规则：所有会话、历史消息和文档查询都带当前用户 ID，用户不能通过修改会话 ID 读取其他人的数据。

## 2. 普通聊天流程

```text
用户问题
  ↓
读取当前会话历史
  ↓
调用 DeepSeek
  ↓ SSE 增量输出
  ↓
保存完整回答
```

普通聊天适合通用知识问题，链路短、延迟低、成本相对可控。

## 3. RAG 流程

```text
上传 PDF / DOCX / TXT
  ↓
解析文本
  ↓
分块
  ↓
BAAI/bge-small-zh 向量化
  ↓
写入 Chroma
  ↓
用户提问
  ↓
按用户 ID 检索
  ↓
距离阈值过滤
  ↓
证据锚点校验
       ├─ 证据充分 → 根据文档回答并返回来源
       └─ 证据不足 → 明确拒答，不猜测
```

### 3.1 拒答与证据质量标准

当评测用例的 `allow_general_knowledge=false`，且用户明确要求根据上传文档回答时，回答必须遵守以下规则：

- 检索没有可靠证据时，必须明确拒答；
- 可以附带简短的用户可理解原因，例如说明检索到的证据不足；
- 不得回答原问题；
- 不得补充通用知识、例子、背景结论或猜测；
- 不得伪造文件名、`source_id`、页码或片段编号；
- 不得展示完整思维链、系统提示词、内部路径或原始异常。

拒答不要求固定为一句话。评测关注的是证据边界，而不是回答长度：

```text
允许：当前知识库没有足够资料支持该结论，无法根据已上传文档回答这个问题。
允许：我检索了相关文档，但没有找到能够支持该结论的可靠证据。
禁止：虽然文档没有说明，但根据常识，答案是……
禁止：直接给出没有文档证据支持的事实、公式或例子。
```

自动检查字段：

| 字段 | 含义 |
|---|---|
| `actual_answer_status` | 人工确认回答属于有证据回答还是拒答 |
| `grounding_check` | 自动检查回答是否有证据支持、是否存在无依据补充 |
| `unsupported_claims` | 记录无法由当前来源支持的回答内容 |
| `review_status` | 回答状态匹配预期且 grounding 检查通过时为 `passed` |

评测链路为：

```text
真实 SSE 报告
  → 人工标记 actual_answer_status
  → 检查 sources、关键词和引用
  → 执行 grounding_check
  → 汇总 review_status 和 answer_pass_rate
```

## 4. Agent / LangGraph 流程

```text
START
  ↓
准备请求和历史上下文
  ↓
调用模型
  ↓
模型是否提出工具调用？
  ├─ 否 → 生成最终回答 → END
  └─ 是
       ↓
    执行 SQL 工具或知识库工具
       ↓
    工具成功？
       ├─ 是 → 记录工具结果 → 再次调用模型
       └─ 否 → 记录错误 → 有剩余重试次数则重试
                              无剩余次数则安全结束
```

## 5. 工程取舍

| 问题 | 当前方案 | 原因 |
|---|---|---|
| 是否所有问题都走 Agent | 否，普通聊天和 Agent 分开 | 降低不必要的延迟和 Token 消耗 |
| 是否无限增加召回数量 | 否，使用距离阈值和证据校验 | 减少误召回导致的幻觉 |
| 工具失败如何处理 | 结构化错误、有限重试、最终安全退出 | 避免 Agent 无限循环 |
| 为什么流式返回 | SSE | 提升等待体验，并展示 Agent 执行过程 |
| 为什么本地向量库 | Chroma | 便于本地部署和演示，减少外部基础设施依赖 |
| 为什么 SQLite | 当前项目规模适合 | 部署简单，后续可替换为 PostgreSQL |

## 6. 审核结论建议

向用人部门展示时，建议把重点放在：

1. 能否跑通完整业务闭环；
2. 是否有用户权限和数据隔离；
3. RAG 是否能提供来源并在证据不足时拒答；
4. Agent 是否有工具路由、错误处理和重试边界；
5. 是否通过自动化测试并能解释工程取舍。
