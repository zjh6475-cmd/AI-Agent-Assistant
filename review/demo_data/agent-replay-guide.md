# AI-Agent-Assistant 回放展示说明

这份说明供聊天123的项目详情页使用。页面不直接调用模型，而是读取
`agent-replay-bundle.json`，按 `events` 顺序播放步骤。

## 推荐页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ AI-Agent-Assistant：企业知识库 Agent                         │
├──────────────┬──────────────────────┬────────────────────────┤
│ 上传文档     │ 用户问题与回答        │ 检索证据                │
│              │                      │                        │
│ 文件名       │ 问题：...             │ 来源文件                │
│ 解析完成     │                        │ chunk / 片段            │
│ 向量化完成   │ Agent 正在处理...     │                        │
├──────────────┴──────────────────────┴────────────────────────┤
│ 执行步骤时间线：解析 → 检索 → 证据校验 → 回答                │
└──────────────────────────────────────────────────────────────┘
```

## 展示顺序

### 场景一：有依据回答

显示问题：

> 根据我上传的公司报销制度，差旅住宿每天的上限是多少？需要提供什么材料？

重点展示：

- 文档中确实有 450 元、300 元和报销材料要求；
- 回答只使用上传文档中的内容；
- 结果下方显示来源文件和章节；
- 说明这是“回答 + 证据”的 RAG 闭环。

### 场景二：证据不足拒答

显示问题：

> 根据我上传的公司报销制度，公司下一年度的总预算是多少？

重点展示：

- 检索到了报销制度，但没有预算金额；
- 系统没有用常识或猜测补答案；
- 页面显示“证据不足，明确拒答”；
- 说明 RAG 的目标不是强行回答，而是控制答案边界。

### 场景三：Agent 调度与来源

显示问题：

> 请根据我上传的 Transformer 文档，说明 Attention 的作用。

重点展示：

- LangGraph 判断需要知识库工具；
- 检索到 3 个相关片段；
- 经过证据校验后生成带来源回答；
- 页面可展示历史评测中的 4513 Token 和 19.7 秒响应时间，但必须标注为历史运行指标。

## 页面下方的补充技术说明

即使 HR 没有看到所有代码，也可以通过以下卡片了解完整工程：

| 技术点 | 项目中的实现 | 展示价值 |
|---|---|---|
| 文档处理 | FastAPI 上传、解析、切片 | 不是只把文本粘贴给模型 |
| 向量检索 | BAAI/bge-small-zh + Chroma | 支持按文档内容检索 |
| Agent 编排 | LangGraph 条件路由和工具调用 | 能解释 Agent 如何做决定 |
| 证据控制 | 距离阈值 + evidence guard | 降低 RAG 幻觉 |
| 流式体验 | SSE 的 token、step、sources、done 事件 | 用户能看到处理中间状态 |
| 数据安全 | user_id 过滤会话和向量结果 | 防止跨用户读取资料 |
| 工程质量 | pytest、GitHub Actions、Docker Compose | 证明项目能测试和部署 |
| 可靠性 | 有限重试、错误脱敏、备份恢复 | 不是一次性 Demo 脚本 |

## 必须区分的标签

页面应同时显示：

- `真实运行结果回放`：来自已有评测记录，例如 `rag-003`；
- `演示文档场景`：根据项目演示文档整理，用于稳定展示问答和拒答效果；
- `离线回放，不产生新的 API Token 消耗`：避免 HR 误以为当前正在调用线上模型。
